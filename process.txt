# ════════════════════════════════════════════
# HOW IPFS STORAGE WORKS IN THIS PROJECT
# ════════════════════════════════════════════

# Every record gets its own IPFS CID:
#
# User signup →         POST /api/auth/user/register
#   → User JSON pinned to IPFS
#   → CID saved in db/index.json
#   → Console: 📌 User saved to IPFS — CID: Qm...
#
# Create election →     POST /api/elections
#   → Election JSON pinned to IPFS
#   → Console: 📌 Election stored on IPFS — CID: Qm...
#
# Add candidate →       POST /api/candidates  (with photo)
#   → Photo file pinned to IPFS  →  imageCid: Qm...
#   → Metadata JSON pinned separately  →  _cid: Qm...
#   → Console: 📌 Candidate photo stored on IPFS — CID: Qm...
#   → Console: 📌 Candidate metadata stored on IPFS — CID: Qm...
#
# Voter registration →  POST /api/voter/register  (with ID doc)
#   → ID document file pinned to IPFS  →  docCid: Qm...
#   → Registration JSON pinned separately  →  _cid: Qm...
#
# Cast vote →           POST /api/vote/cast
#   → Vote record JSON pinned to IPFS  →  voteRecordCid: Qm...
#   → Audit log JSON pinned separately  →  auditCid: Qm...
#   → Console: 📌 Vote record stored on IPFS — CID: Qm...
#   → Console: 📌 Audit log stored on IPFS — CID: Qm...

     http://localhost:5000/api/admin/ipfs-trail/elections

     http://localhost:5000/api/admin/ipfs-trail/votes

curl http://localhost:5000/api/ipfs/snapshot

# ════════════════════════════════════════════
# WHAT TO SAY IN DEFENSE
# ════════════════════════════════════════════

# "We replaced MongoDB with IPFS as our primary database.
#  Every record — user registrations, elections, candidates,
#  voter forms, and vote records — is individually pinned to IPFS
#  via Pinata and gets a unique content identifier (CID).
#
#  The CID is a cryptographic hash of the data — if anyone
#  tampers with a record, the CID would change, making
#  manipulation immediately detectable.
#
#  We maintain a local index mapping IDs to CIDs, and the
#  entire index snapshot can itself be pinned to IPFS —
#  creating a fully verifiable, tamper-evident audit trail
#  with no central database."
